# RentTrack Onboarding & Multi-Property Dashboard

Welcome to **RentTrack**, a modern, production-ready onboarding and property management dashboard for Paying Guest (PG), hostels, and lodging businesses. Built with React, TypeScript, and Tailwind CSS.

---

## 🗺️ Google Cloud Platform (GCP) Setup Instructions

To enable the Google Maps search and location pinning capabilities, you must configure a Google Cloud Project with the Maps JavaScript, Places, and Geocoding APIs. Follow these step-by-step instructions:

### 1. Create a Google Cloud Project
1. Go to the [Google Cloud Console](https://console.cloud.google.com/).
2. Click the project dropdown in the top navigation bar and select **New Project**.
3. Set the project name to **RentTrack** (or a name of your choice) and click **Create**.

### 2. Enable Required APIs
You need to enable three APIs for full functionality (autocomplete, maps rendering, and address parsing):
1. Navigate to **APIs & Services > Library** via the left menu.
2. Search for and click **Maps JavaScript API**, then click **Enable**.
3. Return to the Library, search for and click **Places API**, then click **Enable**.
4. Return to the Library, search for and click **Geocoding API**, then click **Enable**.

### 3. Generate an API Key
1. Go to **APIs & Services > Credentials**.
2. Click **+ Create Credentials** at the top of the page and select **API key**.
3. A modal will appear displaying your new API key. Copy this key.

### 4. Restrict the API Key (Recommended for Production)
To prevent unauthorized usage of your API key, configure domain restrictions:
1. On the **Credentials** page, click the pencil icon next to your newly created API key to edit it.
2. Under **Application restrictions**, select **Websites (HTTP referrers)**.
3. Under **Website restrictions**, click **Add** and enter your Vercel deployment domain or staging domains, for example:
   - `*.vercel.app`
   - `https://your-custom-domain.com/*`
4. Under **API restrictions**, select **Restrict key**, then select **Maps JavaScript API**, **Places API**, and **Geocoding API** from the dropdown.
5. Click **Save**.

### 5. Configure Local Environment Variables
In your local workspace root directory, create a `.env.local` file (if it doesn't already exist) and define the API key:

```env
NEXT_PUBLIC_GOOGLE_MAPS_KEY=AIzaSyYourActualApiKeyHere_xyz
```

*Note: In Vite-based applications, you can also map `VITE_GOOGLE_MAPS_KEY` to this variable, or load it from the window/environment config. The onboarding wizard reads this key to initialize the map and places autocomplete service.*

## 🛠️ Architecture & Core Features

### 🔐 Authentication & Gating (`LoginPanel.tsx` & `App.tsx`)
- **Stripe/Airbnb-inspired Split Screen**: Split layout on desktop featuring a slow-moving animated dots network canvas on the left, and modern sign-in / signup cards on the right. Collapses to full-screen forms on mobile.
- **Robust Registration Forms**: Collects Full Name, Email, Password, Indian Phone Number (+91 format validation), Property Type, and Business Name.
- **Inline Error Handling**: Replaces all native alert boxes with local React state and red inline warning blocks under inputs.

### 🧙 Onboarding Wizard (`OnboardingWizard.tsx`)
- **Step 1: Find/Add Property**: Implements Google Places Autocomplete restricted to India. Selecting a place automatically calls the Places Details API to fetch structural details (formatted name, coordinates, address, city, state, postal code, phone) and renders a Google Map pinned to the coordinates with an info card popup. A manual override bypass option is provided.
- **Step 2: Type & Structure**: Configures property type cards (PG, Hostel, Co-living, etc.), floor counts, room counts, and sharing styles (Single, Double, Triple, Quad) with a live totals summary widget.
- **Step 3: Owner Profile & Branding**: Pre-fills owner profile info, allows editing, and handles local logo/photo file upload preview.

### 🏢 Multi-Property Isolation (`App.tsx` & Dashboard)
- **Active Property State**: Active property context is isolated in the root level state (`activePropertyId`).
- **Data Filtering**: Guest lists, billing profiles, occupancy details, and complaints are dynamically filtered and mapped based on the active property, preventing cross-property data leaks.
- **Header Switcher**: A dropdown switcher in the main header allows switching properties instantly, viewing property type badges, and triggering the Onboarding Wizard in `isAddMode = true` to register a new property.

npm install
